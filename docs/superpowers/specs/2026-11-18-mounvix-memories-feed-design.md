# Mounvix «Воспоминания» — спецификация

**Дата:** 2026-11-18  
**Статус:** проект для пользовательской проверки; реализация не начата.

## 1. Цель и границы

Добавить в Mounvix серверные подборки «Воспоминания» из фото и видео, отдельную вкладку Android, отметку прочтения и локальные уведомления без Google. Подборка содержит до настроенного количества файлов, изменённых в заданном временном периоде.

Первый этап реализует только «Воспоминания». Тип «Новое на сервере», WebSocket и музыкальная лента не входят в этот объём. AI, распознавание EXIF, копирование исходных файлов и полная переиндексация при каждом HTTP-запросе также не нужны.

## 2. Существующий контекст

- Go-сервер уже умеет перечислять фото/видео в текущей папке, определять поддерживаемые изображения и видео, строить миниатюры и отдавать файлы через авторизованные `/api/v1/thumbs` и `/api/v1/file`.
- API сейчас опирается на веб-сессию `mvx`; отдельного Android-профиля Mounvix и API-входа нет.
- Настройки сервера хранятся в `config.json`; фоновые задания уже используются в других пакетах. Серверной ленты и её хранилища пока нет.
- Android использует Compose и WorkManager; нижняя навигация сейчас содержит «Файлы», «Избранное», «Недавние» и «Серверы».
- Общая продуктовая спецификация описывает feeds, периоды, расписание, WorkManager и локальные уведомления.

## 3. Архитектура

### 3.1 Серверная генерация и хранение

Добавить пакет `server/internal/feeds` с отдельными обязанностями:

1. Загружать и атомарно сохранять конфигурацию генерации и ограниченный архив карточек в `DataDir`.
2. Запускать сканирование только по расписанию и только по явно выбранным корням. По умолчанию генерация выключена; включение и параметры доступны администратору в настройках веб-панели.
3. При сканировании использовать имеющиеся правила классификации медиа (`media.Supported`, `media.IsVideo`), брать только файлы, изменённые в пределах настроенного периода, упорядочивать их по времени изменения и детерминированно выбирать до N файлов с равномерным распределением по временному диапазону (при совпадении времени — по root/path). Не читать содержимое файлов для анализа и не копировать исходники.
4. Создавать карточку на расписанный слот, содержащую до настроенного лимита ссылок на фото/видео. ID детерминирован для одного слота, чтобы повторный запуск не создавал дубликат.
5. Сохранять прочитанность отдельно по имени пользователя. Удалять старые карточки по настроенному сроку хранения.

Параметры: включено/выключено, корни, дни и время запуска, quiet hours, период медиа, максимум элементов, срок хранения. Quiet hours сервера откладывают генерацию до следующего разрешённого слота; quiet hours Android подавляют только локальные уведомления. Предлагаемые стартовые значения после включения: 7 дней периода, до 8 медиа на карточку, 30 дней хранения. Поскольку генерация выключена по умолчанию, включение и выбор корней остаются явными действиями администратора.

Сканер выполняется в фоне, не внутри обработчика API; остановка сервера/контекста отменяет работу. Сканирование не должно обходить границы выбранных корней и ограничено 20 000 записями файлов или 30 секундами на запуск (что наступит раньше); при достижении предела сервер пишет предупреждение, не продолжая работу без ограничения. Медиа без доступного файла или миниатюры пропускается при выдаче.

### 3.2 Сессия для Android

Добавить `POST /api/v1/session`, принимающий учётные данные Mounvix, проверяющий их существующим хранилищем пользователей и устанавливающий ту же сессию `mvx`, что используется веб-панелью. Неверные данные дают `401`; успешный ответ не возвращает пароль. Android сохраняет cookie через OkHttp и повторно входит после истечения сессии. Настройки этого API-профиля (адрес сервера и учётная запись) независимы от WebDAV/SMB/SFTP.

### 3.3 API ленты

- `GET /api/v1/feeds?since=<RFC3339>&limit=<N>` возвращает карточки новее курсора по возрастанию времени генерации и новый курсор синхронизации. При первом запросе без `since` используется начало периода хранения; `limit` ограничивается сервером, чтобы ответ оставался малым.
- `POST /api/v1/feeds/{id}/read` помечает карточку прочитанной для текущего пользователя; повторный вызов идемпотентен.
- Оба endpoint требуют действующую сессию. Каждый вложенный файл фильтруется по ACL пользователя; карточка без доступных вложений не выдаётся. Все URL миниатюр/файлов относительные и ведут на существующие защищённые API.
- Ошибки используют корректные HTTP-коды: `400` для некорректного запроса, `401` для отсутствующей/истёкшей сессии, `404` для неизвестного ID, `5xx` для серверной ошибки; JSON-ответы не содержат локальных абсолютных путей.

### 3.4 Android-клиент

Добавить один активный профиль Mounvix API с URL и учётными данными, сетевой репозиторий с cookie-сессией, модель карточки и состояние экрана во ViewModel. Работа с сетью остаётся асинхронной; пустая лента не считается ошибкой. Многосерверное управление Mounvix API-профилями не входит в первый этап.

Уникальная задача WorkManager запускается не чаще минимально разрешённого Android интервала 15 минут. Она использует сохранённый курсор, обрабатывает новые ID ровно один раз и создаёт локальное уведомление для новой подборки, если уведомления включены и наступило разрешённое время. Сбой сети не сбрасывает курсор и повторяется по политике WorkManager. На этом этапе WebSocket не реализуется.

## 4. UX

- В нижней навигации добавить вкладку «Воспоминания»; карточки сгруппировать по дате генерации, показать заголовок и миниатюры.
- Открытие карточки помечает её прочитанной. Нажатие на медиа открывает просмотр через Mounvix API; недоступные элементы не должны ломать всю карточку.
- Экран имеет состояния загрузки, непустой ленты, пустой ленты, ошибки/офлайна и ручного повтора.
- Настройки Android: включение/выключение уведомлений и quiet hours. Настройки сервера определяют расписание и параметры генерации.
- UI следует существующей Material 3 теме и остаётся пригодным для узких экранов и динамического размера текста.

## 5. Тестирование и критерии приёмки

### Go

- Генератор фильтрует изображения/видео по выбранному периоду, пределу количества и выбранным корням; не включает неподдерживаемые типы.
- Повтор запуска для того же слота не дублирует карточку; запись/чтение JSON переживает перезапуск; срок хранения удаляет только просроченное.
- ACL фильтрует каждый элемент и запрещает чтение/отметку чужой карточки.
- API проверяет сессию, валидацию параметров, курсор, лимит, отметку read и коды ошибок.
- Существующие media, auth и API тесты не регрессируют.

### Android

- Тесты репозитория: вход, cookie, истёкшая сессия, разбор карточек, cursor-синхронизация и ответы сервера.
- Тесты WorkManager/планировщика: ID-дедупликация, повтор после сети, выключенные уведомления и quiet hours.
- Тесты ViewModel/экрана: загрузка, пустое, ошибка, обновление и отметка прочитанности.
- Проверить сборку приложения и по возможности живой поток на эмуляторе; если эмулятор недоступен, явно отметить это, не подменяя unit-тестами.

### End-to-end

С настроенным Mounvix test server: создать тестовые медиа с разным временем изменения, включить один корень, дождаться/запустить генерацию, проверить авторизованную выдачу и фильтрацию ACL, загрузить thumbnail/original через Android, отметить карточку прочитанной и убедиться, что после повторного опроса уведомление не дублируется.

## 6. Явно отложено

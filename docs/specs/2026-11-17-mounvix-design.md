## 1. Цель и границы

Mounvix — собственный (не клон, без чужого кода) продукт «NAS в телефоне»:

- **Android-приложение** (`com.mounvix.app`, Kotlin + Jetpack Compose): файловый менеджер уровня Owlfiles, который умеет работать с локальными файлами телефона, SAF-деревьями, SMB, WebDAV, SFTP/FTP и с нашим сервером; отдельно — галерея фото/видео, автозагрузка с телефона, лента-подборки, уведомления, шаринг, AI-разметка фото.
- **Серверный агент** (`mounvix-server`, Go, один статический бинарник под aarch64/armv7/mips/mipsle/i386/x86_64): лёгкий Web-UI (панель + медиа-галерея), собственный WebDAV, управление доступами к папкам, пользователи, статистика, шеринг, лента/уведомления, AI-очереди. Устанавливается как `opkg` (Keenetic/Entware), `.deb` (Ubuntu/Debian), `.tar.gz` (прочий Linux). Запуск на одном ядре, низкое потребление памяти.
- **Два режима**: «простой» — приложение само ходит к любым WebDAV/SMB/SFTP-шарам (как Owlfiles); «расширенный» — на сервере установлен Mounvix-агент, доступны панель, медиатека, автозагрузка с телефона, AI, подборки, шаринг, статистика.

Вне границ текущей версии: iOS-приложение, NFS-клиент на телефоне, семантический поиск, PAM-аутентификация, музыкальная лента (уточнение в §19). OneDrive и прочие облака — позже; Google Drive — плагином rclone (§22).

## 2. Зафиксированные решения (2026-11-17)

2. Протоколы v1: WebDAV (+HTTPS), SMB2/3, SFTP; FTP — со следующей итерацией; NFS/облака — позже.
3. Уведомления без Google: серверные подборки + локальные уведомления на телефоне (WorkManager/foreground), WebSocket при открытом приложении.
4. AI: on-device обработка по умолчанию (ML Kit bundled — без Google Play Services; TFLite эмбеддинги лиц для кластеризации) + опциональный внешний OpenAI-совместимый endpoint в настройках.
5. Лицензия GPL-3.0 + NOTICE.
6. Языки: RU + EN, расширение словарями JSON без пересборки (как в keenetic-smb-ui).
7. Порт сервера — **48100** (HTTP), публикация через KeenDNS `https://mounvix.firma.crazedns.ru` (TLS терминирует KeenDNS/роутер; запись переключить на HTTP:48100).

10. Автообновление + откат в приложении и в Web (бэкап прошлой версии, health-check); параллельно работают opkg/apt-обновления.
11. Автозагрузка с телефона — ключевая фича, режимы A–E (§10).
12. Внешний cron не требуется — внутренний планировщик сервера.
13. Сборки — скриптами (Go-матрица + Android); GitHub Actions — опционально для релизного пайплайна.
14. QA — playwright-extension по Web-UI + adb-визуалка Android на эмуляторе; реальная установка на роутер (Entware) и LXC на `proxmox-250` (192.168.165.250).
15. Доступ к роутеру/Entware/WebUI — из Basic Memory; правку KeenDNS-записи Mounvix выполняем через RCI/SSH при деплое.
16. Плагины (манифест + процесс-плагины + каталог index.json) входят в этот же релиз (§22); API плагинов закладывается с M0.
17. Серверный бэкап шар входит в этот же релиз (§23): локальные пути/второй диск/USB, смонтированные SMB/NFS, WebDAV (Yandex Disk, Mail.ru); Google Drive — плагин rclone; задания индивидуально по папкам, расписание + «Бэкап сейчас» + восстановление.
18. Облачный QA: Yandex-аккаунт zege368@yandex.ru (~200 ГБ; браузер — только playwright-extension); для WebDAV-загрузки нужен app-password — запросим на этапе QA, храним в Basic Memory.
19. Любой браузерный доступ — только через playwright-extension.

## 3. Пользовательские сценарии (v1)

- **S1. Приложение как Owlfiles**: добавил сервер (SMB/WebDAV/SFTP или наш Mounvix), вижу файлы, загружаю/скачиваю, открываю, переименовываю, удаляю, делюсь.
- **S2. Автозагрузка камеры**: выбрал папку DCIM/Camera → сервер `/photo`; фото загружаются по Wi-Fi/на зарядке; на телефоне остаются согласно режиму (A–E); галерея листается из локального кэша, недостающее подтягивается с сервера.
- **S3. Медиатека на сервере**: в Web-панели открываю «Медиа», вижу галерею по датам, видео проигрывается, фото листается; создаю ссылку «поделиться» на альбом.
- **S4. Люди и категории**: телефон по ночам размечает новые фото (лица/сцены), я подтверждаю имена; в Web — альбомы «Люди», фильтры по категориям; при выключенном внешнем AI фото не уходят за пределы моих устройств.
- **S5. Подборки**: сервер по расписанию формирует «Воспоминания» (N фото/видео за период); телефон раз в 30 минут забирает новинки и показывает уведомление; тап — лента в приложении.
- **S6. Установка**: `opkg install mounvix` на Keenetic → сервис поднялся, панель `http://192.168.160.1:48100`, WebDAV `/dav`; apt install на Ubuntu (LXC на proxmox-250) → то же через systemd.
- **S7. Обновление**: в Web-панели «Проверить обновления» → скачивание/замена бинарника, откат при неудаче; в приложении — «Обновить» с GitHub Releases, кнопка отката к предыдущей.

## 4. Архитектура

```
 Android (Kotlin/Compose)                Web (браузер)
   │  WebDAV/SMB/SFTP + /api/v1/ws        │ HTTPS (KeenDNS) → HTTP:48100
   ▼                                       ▼
 ┌──────────── Mounvix server (Go, static) ────────────┐
 │ HTTP:   Web UI (templates+htmx), JSON API v1, WS    │
 │ WebDAV: /dav (Basic auth), PROPFIND/PUT/Range       │
 │ Auth:   users/sessions/ACL (SQLite)                 │
 │ Index:  SQLite (files, media, ai, feeds, shares)    │
 │ Media:  thumb cache, video streaming, Range         │
 │ AI:     job queue (on-device worker / external API) │
 │ Updater: GitHub releases + rollback                 │
 └──────────────┬──────────────────────────────────────┘
                │  локальные пути (уже смонтированные SMB/NFS/диски)
                ▼
        Файлы на дисках роутера/сервера
```

- Сервер **не монтирует** шары сам: он работает с уже смонтированными путями (это забота системы/keenetic-smb-ui).
- Приложение в расширенном режиме использует: WebDAV для передач (просто и надёжно) + JSON API для метаданных, ленты, AI, шаринга, обновлений.
- В простом режиме сервер не нужен: приложение — самостоятельный клиент WebDAV/SMB/SFTP.

## 5. Серверный агент (Go)

### 5.1 Стек и ограничения
- Go 1.22+, `CGO_ENABLED=0`, статический бинарник; чисто-Go SQLite (modernc.org/sqlite) — без C-зависимостей под mips.
- Зависимости: `x/net/webdav`, `x/crypto/bcrypt`, `go:embed`, htmx (один JS-файл), без тяжёлых фреймворков.
- Бюджет: бинарник ≤ 25 МБ (архитектуры Entware), RSS ≤ 50 МБ, CPU — один поток-сканер с троттлингом, нулевые фоновые циклы при простое.

### 5.2 Структура кода
```
server/
├─ cmd/mounvix-server/main.go
├─ internal/config/     конфиг JSON + флаги
├─ internal/httpx/      middleware, сессии, CSRF
├─ internal/auth/       логин, пароли, роли, регистрация
├─ internal/users/      пользователи, импорт, ACL
├─ internal/webui/      шаблоны, htmx, статика (embed)
├─ internal/api/        JSON API v1 + WS
├─ internal/dav/        WebDAV поверх ACL
├─ internal/fsx/        пути, права, листинг
├─ internal/index/      SQLite-индекс файлов/медиа
├─ internal/media/      превью, кэш, Range-стриминг
├─ internal/ai/         очередь и результаты
├─ internal/feeds/      подборки, расписание
├─ internal/share/      ссылки
├─ internal/updater/    self-update + rollback
├─ internal/logs/       лог в памяти/файле
└─ internal/version/    версия, build-инфо
```
### 5.3 Размещение (Keenetic/Entware и Debian)
| | Entware (Keenetic) | Debian/Ubuntu (deb) |
|---|---|---|
| Бинарник | `/opt/bin/mounvix-server` | `/usr/bin/mounvix-server` |
| Конфиг | `/opt/etc/mounvix/config.json` (Conffiles) | `/etc/mounvix/config.json` |
| Данные/кэш | `/opt/var/mounvix/` | `/var/lib/mounvix/` |
| Локали | `/opt/etc/mounvix/locales/*.json` | `/etc/mounvix/locales/*.json` |
| Автостарт | `/opt/etc/init.d/S99mounvix` | `systemd mounvix.service` |
- Порт по умолчанию: 48100 (HTTP; в конфиге можно изменить).
- От root по умолчанию (запись в SMB/NFS-монтирования); пользователь сервиса настраивается.

### 5.4 HTTP API v1 (JSON, Bearer-токен; Web-UI — cookie+CSRF)
| Метод/путь | Назначение |
|---|---|
| GET /health | статус, версия, uptime (без auth) |
| POST /api/v1/auth/login | {username,password} → {token,expires,user} |
| POST /api/v1/auth/logout, GET /auth/me | сессия |
| GET /api/v1/locales, /locales/{code} | словари (без auth) |
| GET /api/v1/roots | доступные папки/корни для пользователя |
| GET /api/v1/ls?root=&path= | листинг (метаданные, размеры, mtime, mime, isMedia) |
| GET /api/v1/files/meta?path= | один файл |
| GET /api/v1/thumbs?path=&w= | превью (JPEG/WebP из кэша) |
| PUT /api/v1/thumbs?path= | загрузка превью с телефона |
| GET /api/v1/feeds?since= | подборки |
| POST /api/v1/feeds/{id}/read | отметка прочтения |
| GET /api/v1/ai/jobs?limit= | получить задания (faces/labels/ocr) |
| POST /api/v1/ai/jobs/{id}/result | отправить результат |
| GET/POST /api/v1/shares, DELETE /shares/{id} | шеринг-ссылки |
| GET /api/v1/updates/check | проверка версии |
| POST /api/v1/updates/apply, /rollback | обновление/откат (admin) |
| GET /api/v1/ws | WebSocket: feed.new, update.status |
| /api/v1/admin/* | users, settings, stats, logs (admin) |
| /dav/* | WebDAV (Basic auth) |

Передачи файлов (upload/download) — через WebDAV (Range, большие файлы); API — только метаданные.

### 5.5 Данные (SQLite, `data/mounvix.db`)
`users` (id, username, passhash, role, active, source, created_at) · `sessions` (token_hash, user_id, expires, ua) · `acl` (user_id, root/path_prefix, perms) · `settings` (key, value_json) · `index_files` (path, root, size, mtime, mime, kind, updated_at) · `media_meta` (path, w, h, duration, taken_at, thumb_state) · `ai_jobs` (id, path, type, status, payload_json, result_json, updated_at) · `faces` (path, cluster_id, name, bbox_json) · `feeds` (id, kind, title, body_json, created_at) · `feed_reads` (user_id, feed_id) · `shares` (id, token_hash, path, expires, password_hash, allow_upload, created_by) · `audit_log` (ts, user, action, path, ip).
Схема версионируется (`PRAGMA user_version`), миграции — встроенные шаги.

### 5.6 Конфиг и локали
`config.json`: port, data_dir, roots[], tls{...}, update{enabled,channel,repo}, restart_cmd, external_ai{}, registration{enabled,auto_activate}, session_ttl, max_upload_mb, thumbs{max_px,quality}, feeds{enabled,slots[]}, logs{file,level}.
Локали: встроенные ru/en (`embed`), материализуются при первом старте, при старте merge новых ключей без перезаписи пользовательских значений; `GET /api/locales*` без auth (нужно для экрана логина).

## 6. Web UI

### 6.1 Страницы
- **Вход** (логин/пароль, язык, версия).
- **Обзор**: диск/занято, корни, последние действия, статус сервисов, быстрые ссылки.
- **Доступ к папкам**: список корней (path, размер, права), добавление/удаление, ACL для пользователей.
- **Пользователи**: список, создание, импорт (OS/Samba), сброс пароля, pending-заявки (регистрация), роли.
- **Медиа**: галерея (сетка с датами, фильтры «фото/видео», поиск по имени), лайтбокс с листанием и видео-плеером (Range), альбомы «Люди»/«Категории» (после AI), кнопка «Поделиться».
- **Шары**: список ссылок, создание (срок, пароль, право загрузки), отзыв.
- **Лента**: превью подборок, расписание.
- **Настройки**: общие (порт, рестарт), обновления (авто, канал, кнопка отката, история), регистрация, лента/расписание, AI (внешний endpoint, ключ), языки (список словарей + инструкция), логи (просмотр/tail), экспорт/импорт конфига (секреты не выводятся).
### 6.2 Технические требования
- Серверный рендер + htmx (без сборки SPA), CSS ~30 КБ, JS только htmx + мелочи; никакого React/Node на устройстве.
- Работает на 1 ядре, без шрифтов из интернета, mobile-friendly (одна колонка), тёмная/светлая тема (по системе + переключатель).
- Все страницы без JS-фреймворка; деградация — базовые формы.

### 6.3 i18n
Словари `locales/ru.json|en.json`; добавление языка — файл в каталог без пересборки; UI показывает путь и кнопку «Скачать шаблон».

## 7. Android-приложение

### 7.1 База
- Kotlin, Jetpack Compose Material3, MVVM; модули: `ui/`, `core/`, `data/{local,saf,dav,smb,sftp}`, `data/db` (Room), `sync/` (автозагрузка/кэш), `media/` (Coil-превью, Media3-плеер), `notifications/`, `update/`.
- minSdk 29, target 34; пакет `com.mounvix.app`; подпись — собственный release-keystore (обновления/откат).
- Разрешения: `MANAGE_EXTERNAL_STORAGE` (показ всех файлов телефона, как Owlfiles; основной режим) + SAF как альтернатива; `POST_NOTIFICATIONS`; опционально `READ_MEDIA_*`; WorkManager.
### 7.2 Экраны
- **Онбординг**: приветствие, разрешения (все файлы/SAF/уведомления), добавление сервера.
- **Серверы**: список источников (Телефон, SAF-деревья, WebDAV/SMB/SFTP аккаунты, «сервер Mounvix»), добавление/редактирование/тест соединения, отметка «расширенные функции доступны».
- **Файлы**: браузер источника (breadcrumbs, сортировка, поиск, мультиселект, буфер, переименование, удаление, инфо, open-with, share, upload/download), звёздочки избранного.
- **Избранное / Недавние** (как в FileBox).
- **Галерея**: объединённая лента локальных + серверных фото/видео, группировка по датам, ленивые превью, лайтбокс, видео-плеер, меню «сохранить на телефон / удалить / поделиться».
- **Передачи**: активные/история, пауза/продолжить/повтор, прогресс, лимиты.
- **Подборки**: лента серверных подборок, отметка прочтения, переход в галерею.
- **Настройки**: серверы, автозагрузка (режимы A–E + фильтры + папки), кэш (размер, очистка), уведомления (расписание нельзя менять на телефоне — серверные, только вкл/выкл и quiet hours), язык, тема, обновления (авто/откат), AI (on-device вкл/выкл, внешний сервер), о программе/лицензия.
### 7.3 Учётные данные
Пароли — EncryptedSharedPreferences/Keystore; в Room — только ссылки. Self-signed TLS: переключатель «принимать самоподписанный сертификат» + опция «закрепить отпечаток».
### 7.4 Единый вид и метки
В браузере корни «Телефон» и каждый сервер/шара; при совмещении одного пути с локальным — метки: 📱 только локально · ☁️ только на сервере · ✅ синхронизировано (после успешной загрузки).
### 7.5 Галерея и кэш
- Превью: локальный кэш (WebP/JPEG, LRU, лимит настраивается, дефолт 200 МБ) + серверный кэш; превью сгенерированные телефоном загружаются на сервер (решает HEIC/видео-кодеки).
- Полные файлы — по требованию (скачивание с прогрессом), с кэшированием в кэше приложения по настройке.

## 8. Протоколы и совместимость

### 8.1 WebDAV
- Наш сервер: `/dav`, Basic auth, PROPFIND (depth 0/1/infinity с лимитом), GET/PUT/DELETE/MKCOL/COPY/MOVE/PROPPATCH, Range для скачивания, OPTIONS с DAV: 1,2.
- LOCK: минимальная реализация не в v1; клиенты, требующие LOCK (macOS Finder), честно получат ограничение; QA-матрица: rclone, curl, Windows (WebClient), Android-клиенты, iOS Files (проверить на LXC).
- Простой режим приложения: WebDAV-клиент с Basic/Digest (Digest — по необходимости), HTTPS, самоподписанные сертификаты (настройка), повторные попытки/таймауты.
### 8.2 SMB/SFTP/FTP
SMB2/3 — библиотека smbj (client); SFTP — sshj/parallel; FTP — отложен. Работа через Android-сеть с явным статусом ошибок.
### 8.3 TLS/сертификаты
KeenDNS меняет TLS на своей стороне (валидный сертификат), сервер внутри — HTTP:48100. В LAN: HTTP или самоподписанный HTTPS (порт тот же). Приложение умеет оба.
### 8.4 KeenDNS
`https://mounvix.firma.crazedns.ru` → HTTP 48100 (сейчас в записи стоит 443 — меняем при деплое). Доступ по IP `http://192.168.160.1:48100` тоже поддерживается.

## 9. Пользователи, роли, регистрация

- Дефолт: `admin` / `1234567890` (сид при первом старте; смена — в панели).
- Роли: `admin` (всё), `user` (корни/папки по ACL: read / write).
- Импорт учёток: OS (`getent passwd`, имена без паролей), Samba (`pdbedit -L`, если установлена) — создаются записи с временным паролем, показываемым один раз админу; повторный импорт обновляет имена, не пароли.
- Регистрация (только расширенный режим): форма на странице входа при `registration.enabled=true`; заявка `active=0` до подтверждения (если `auto_activate=false`).
- Сессии: token (32 байта, хэш в БД, TTL 30 дней), Web-UI cookie + CSRF, WebDAV — Basic.
- Аудит: логины, изменения прав, шары, обновления.

## 10. Автозагрузка (ключевая фича)

Для каждой папки-источника на телефоне — своё правило: локальная папка → корень сервера + режим + фильтры.

| Режим | После успешной загрузки | Что остаётся на телефоне |
|---|---|---|
| A. Копия | ничего не удалять | всё |
| B. Очистка | удалить загруженное | только невыгруженное |
| C. Последние N | удалить загруженное, кроме последних N | N самых свежих загруженных + невыгруженное; N ∈ {10,50,100,500,1000,1500,3000} + своё число |
| D. Последние M дней | удалить загруженное старше M дней | загруженное моложе M дней + невыгруженное; M ∈ {1,2,3,7,14,30} + своё |
| E. Гибрид C×D | удалить всё, что старше M дней И не входит в последние N | объединение «последние N» и «моложе M дней» |

Фильтры (включаемые): только фото/видео/все; только новые с момента подключения или с даты; только Wi-Fi; только на зарядке; окно времени (например, 02:00–06:00); исключить скрытые/по маске; исключить системные папки (Screenshots/Telegram/WhatsApp — чекбоксы); лимит размера файла; минимальный возраст файла (не грузить «свежее 5 минут»).
Удаление: только файлов, загруженных через Mounvix (учёт в Room по path+device id); удаление через «Все файлы» (без системных диалогов), SAF-фолбэк; опция «удалять пустые папки после очистки».
Конфликты: по умолчанию пропускать существующий файл того же размера+mtime; опции «заменить, если новее», «сохранять оба (суффикс)»; атомарная загрузка во временный `.part` на сервере через WebDAV PUT.
Очередь: Room `transfers` (state, retry, bytes), WorkManager для периодики + передний сервис для больших партий; пауза/продолжение; отчёт об ошибках в «Передачах»; счётчики в статистике сервера.
Кэш: после загрузки миниатюра фиксируется в локальном кэше → галерея быстрая даже после удаления оригинала.

## 11. Медиа и превью

- Сервер: кэш превью `data/cache/thumbs/<sha1(path)>_<w>.jpg|webp`; фото — декод Go (JPEG/PNG/GIF/WebP), HEIC — только с телефонных превью (или внешний ffmpeg/хелпер, опция); видео — первый кадр с телефона, либо ffmpeg при наличии; стриминг видео — Range/206.
- Web-галерея: lazy-loading, группировка по датам, поиск, фильтры, лайтбокс с жестами/клавишами, кнопки «скачать/поделиться».
- Android: Coil-превью из локального кэша или `/api/v1/thumbs`; предзагрузка следующей страницы; лимиты памяти.

## 12. AI-распознавание

- Задания: `faces`, `labels`, `ocr` (приоритет — faces/labels). Сервер формирует задания на новые фото (`ai_jobs`), телефон забирает по API при Wi-Fi/зарядке (или по кнопке), выполняет on-device:
  - ML Kit bundled: детекция лиц, классификация сцен/объектов; OCR — опционально.
  - TFLite MobileFaceNet (встроенная модель) — эмбеддинги лиц; кластеризация на телефоне; пользователь подтверждает имена; результаты (bbox+cluster+name) уходят на сервер.
- Внешний AI: настройка endpoint (OpenAI-совместимый: base_url, api_key, model, vision-формат) — сервер сам обрабатывает задания (изображение → base64/URL), результаты в ту же схему. Совместим с локальными llama.cpp-серверами владельца.
- Приватность: без внешнего AI фото не покидают устройства; в настройках явный переключатель.
- Панель: «Люди» (альбомы по именам), «Категории» (labels), прогресс задач, ручное переименование/слияние кластеров.

## 13. Лента и уведомления (без Google)

- Сервер: `feeds` генерируются по расписанию (слоты из настроек, дни недели, quiet hours): «Воспоминания» (N фото/видео за период), «Новое на сервере» (с момента прошлого фида), позже — музыкальная лента (уточнение).
- Телефон: WorkManager раз в 15–60 минут (минимум 15) тянет `GET /feeds?since=`, показывает локальное уведомление (канал «Подборки»), тап открывает ленту в приложении. При открытом приложении — WebSocket.
- Настройки на сервере: включено/выкл, слоты, количество, период; на телефоне — включить/выкл, тихие часы.

## 14. Шаринг

- Расширенный режим: `POST /api/v1/shares` → ссылка `/s/{token}` (срок, опциональный пароль, read-only или «загрузка разрешена»); публичная лёгкая страница (галерея/файл, без панели).
- Приложение: экран «Поделиться» — существующие ссылки + создание новой + отправка в системный share sheet; локальные файлы — обычный Android share.
- WebDAV остаётся для клиентов; ACL распространяется и на шары.

## 15. Обновления и откат

- **Сервер**: `GET /api/v1/updates/check` (GitHub Releases API, выбор asset по arch: `mounvix-server_{ver}_{os}_{arch}`), `apply` (скачать → sha256 по `sha256sums.txt` → записать `.new` → запуск через init/systemd с флагом обновления; watchdog: при неудачном старте в течение 60 с вернуть `.prev`). Кнопки в Web: «Проверить», «Обновить», «Откатить», история версий.
- **Веб-свитчер**: `update.enabled` (авто/по кнопке), канал stable (пока один), уведомление админу при выходе новой версии (в панели, не в браузере).
- **opkg/apt**: пакеты публикуются в фиде; `opkg upgrade mounvix`/`apt upgrade` работают параллельно; конфиг сохраняется при переустановке (Conffiles + prerm-бэкап/postinst-восстановление — проверено практикой скилла).
- **Android**: проверка релиза (GitHub API), скачивание APK, установка через `PackageInstaller` с `setAllowDowngrade(true)`; свитчер «авто-проверка»; «Откатить» = установка предыдущего релиза (подпись та же — release-keystore проекта); прогресс и результат в настройках.

## 16. Пакетирование и CI

- Артефакты: `mounvix-server_*_{arm64,arm,mipsle,mips,amd64,386}` (tarball+bin), `mounvix_{arch}_{version}.ipk` (aarch64-3.10, armv7-3.2, mipsel-3.4, mips-3.4, x64-3.2, x86-2.6), `mounvix-server_{version}_amd64.deb`, `sha256sums.txt`.
- `.ipk` — legacy gzip-tar (debian-binary + control.tar.gz + data.tar.gz), `Conffiles: /opt/etc/mounvix/config.json`; prerm копирует живой конфиг, postinst восстанавливает при «маленьком» конфиге; скрипты с `[ -n "$IPKG_INSTROOT" ] && exit 0`.
- Фид: `Packages`/`Packages.gz` (пустая строка между блоками!) как GitHub Release assets (`src/gz mounvix https://github.com/tommilevs/Mounvix/releases/latest/download`), опционально GitHub Pages apt-репо.
- Скрипты: `scripts/build-all.sh` (матрица Go + APK), `scripts/package.sh`, `scripts/feed.sh`, `scripts/release.sh`, `scripts/dev-server.sh`, `scripts/qa.sh`; Actions — по тегу v* (опционально, экономия — локальные сборки).
- Печать версии: `-ldflags "-s -w -X main.version=..."`; воспроизводимость.

## 17. QA-стратегия

- **Go**: unit-тесты (auth, ACL, индексация, thumbs, updater, feeds, shares), httptest-интеграция API, тест WebDAV (rclone/curl в CI-скрипте).
- **Web (playwright-extension)**: вход/выход, «Доступ к папкам», пользователи/регистрация, медиа-галерея (фото/видео), шары, настройки (языки/обновления/AI), мобильный viewport, тёмная тема; визуальная оценка скриншотов.
- **Роутер (Keenetic, aarch64)**: `opkg install` из тестового ipk, сервис стартует, health, WebDAV через curl/rclone, панель в браузере (playwright), перезапуск, `--force-reinstall` с сохранением конфига, upgrade/rollback.
- **LXC (proxmox-250)**: Ubuntu 24.04, `dpkg -i`, systemd-сервис, WebDAV, панель, обновление через релиз.
- **Android (emulator-5554 + adb)**: сценарии S1–S5 (добавление серверов всех типов, автозагрузка на тестовой папке DCIM, режимы A–E, удаление с телефона, галерея с кэшем, подборки/уведомления, обновление/откат) + визуальные скриншоты каждого экрана, логкэт без FATAL/ANR.
- **Регрессия**: перед релизом полный прогон скриптом; артефакты QA хранить до итогового отчёта.

1. `build-all.sh` собирает всё для всех арок; APK подписан release-ключом.

3. playwright-extension сценарий Web-UI (все страницы, мобильный вид, тёмная тема) — PASS с визуальной оценкой.
4. Android: сценарии S1–S5 на эмуляторе, все экраны визуально проверены, FATAL/ANR нет.
5. Автозагрузка (режимы A–E), кэш галереи, лента с уведомлениями, шеринг — проверены на живых данных.
6. Обновление/откат проверены и в приложении, и в Web.
7. Релиз на GitHub с ipk/deb/APK и фидом; README/NOTICE с указанием создателя.
8. Плагины: движок и каталог; установка/включение/выключение примеров; rclone-backup (Google Drive) работает либо честный blocker по токену.
9. Бэкап: задания по папкам, расписание и «Бэкап сейчас», восстановление; локальный и WebDAV-таргеты проверены, Yandex-аккаунт протестирован (app-password).

## 22. Плагины (расширяемость)

- Цель: расширять Mounvix сторонними модулями, не утяжеляя ядро и Web-UI. Установка как у DSH: opkg/apt-пакет либо папка в каталоге плагинов.
- Каталог плагинов: `/opt/etc/mounvix/plugins/<id>/` (Entware) или `/etc/mounvix/plugins/<id>/` (deb); данные плагина — `data/plugins/<id>/`.
- Типы:
  1) **Декларативные** (`plugin.json`): настройки (schema → формы рендерит ядро), пункты меню, виджеты «Обзора», страницы из `pages/*.html` (статический HTML без своего JS), задания по расписанию (команда + таймаут).
  2) **Процесс-плагины**: исполняемый файл, JSON-RPC 2.0 по unix-сокету; возможности: свои страницы (HTML отдаётся в sandbox-iframe), REST-прокси `/api/v1/plugins/<id>/...`, задания по cron, подписка на события (`file.indexed`, `upload.done`, `backup.done`).
  3) WASM — не в v1 (нужен рантайм; опционально позже).
- Манифест: id, name, version, api=1, author, description, icon, capabilities{fs_paths[], net, schedule}, menu[], settings_schema{}, pages[], jobs[], hooks[], endpoints[].
- Каталог-реестр: `index.json` (id, name, version, min_app, arch[], assets{ipk, deb, sha256}, home) с GitHub (сначала `plugins/index.json` в основном репо, позже отдельный `tommilevs/Mounvix-plugins`); страница «Плагины»: установленные, каталог, установка opkg/URL, включение с показом capabilities, обновление, выключение, удаление, логи.
- Лёгкость: манифест-страницы — нативные шаблоны ядра; iframe-страницы грузятся только при открытии; выключенные плагины не потребляют CPU/RAM/JS; базовый бинарник не содержит WASM-рантайма.
- Изоляция исполнения: процесс-плагин запускается отдельно, лимит времени, отдельный лог; ядро не загружает сторонний код в свой процесс.
- Примеры: `hello` (декларативный), `echo` (процесс), боевой `rclone-backup` (Google Drive и прочие облака через rclone; на Keenetic — opkg-пакет rclone, на Ubuntu — apt).

## 23. Бэкап шар (серверный, «расширенный» режим)

- Назначение: бэкап фото/видео/любых файлов с шар во второе место; настраивается в Web-панели и работает независимо от телефона (дополняет автозагрузку камеры с телефона).
- Источники: любые папки, доступные серверу; фильтры: всё/только фото/видео, маски, исключения, по дате, по размеру.
- Цели (адаптеры): локальный путь (второй диск/USB); смонтированная SMB/NFS-шара; WebDAV (streaming PUT, Basic/Digest, самоподписанный сертификат) — покрывает Yandex Disk (`https://webdav.yandex.ru`) и Mail.ru (`https://webdav.cloud.mail.ru`); Google Drive и другие облака — через плагин `rclone-backup` (§22).
- **Задания индивидуально по каждой папке**: источник → цель, фильтр, расписание, режим (append-only по умолчанию), лимит скорости, вкл/выкл, «Бэкап сейчас», пауза.
- Движок: инкрементально (size+mtime; опционально sha256), дозапись temp+rename при обрыве, конкурентность 1, retry/backoff, лимит полосы; манифест в SQLite (`backup_jobs`, `backup_runs`, `backup_files`); на цели по умолчанию ничего не удаляем.
- Расписание: внутренний планировщик (дни/часы), дефолт 03:00; история запусков, ошибки, счётчики (файлы/байты), уведомление в ленте и на дашборде.
- Восстановление: список файлов из манифеста → вернуть выбранные в исходную/новую папку (батч), проверка sha256, если сохранён.
- QA облаков: реальный тест на Yandex-аккаунте `zege368@yandex.ru` (~200 ГБ) через WebDAV; app-password запросим на этапе QA (храним в Basic Memory); Mail.ru — аналогично; браузерные проверки — только playwright-extension.
